# BeatNote — iOS & TestFlight Setup

## Status

The generated iOS app builds and the XCTest UI suite runs on Xcode 27's iOS simulator runtime. A
locally signed development build also launches on an iPhone 15 Pro Max running iOS 27.0.1. Apple
Developer enrollment for distribution and TestFlight setup remain pending; they are not required
for simulator development or the current locally signed device workflow.

The generated `ios/` directory is intentionally ignored. Native configuration must be expressed in
`app.json` or Expo config plugins so `expo prebuild` can reproduce it.

`plugins/withIosSceneLifecycle.js` supplies the UIKit scene manifest and generated
`SceneDelegate.swift` required by the iOS 27 SDK. React Native still starts during
`didFinishLaunchingWithOptions` so Expo Dev Launcher subscribers receive their prepared bridge and
key window; the scene delegate then attaches that existing window to the connected `UIWindowScene`
and forwards scene lifecycle, URL, and user-activity events through `AppDelegate`.

### Physical development build on iOS 27

1. Connect and unlock the iPhone, enable Developer Mode, and trust/pair it with Xcode.
2. Start Metro on the Mac host network. For a wired phone that is not on the same Wi-Fi network,
   identify the Mac-side link-local address (for example with `ifconfig`) and keep Metro listening
   on port 8081.
3. Open `ios/BeatNote.xcworkspace`, select the `BeatNote` scheme and the physical phone, then use
   Product > Run. A CLI build may need `CODE_SIGN_ALLOW_ENTITLEMENTS_MODIFICATION=YES` because the
   Expo configure phase updates development entitlements before signing.
4. If Expo Dev Launcher cannot discover Metro, launch the installed app with a development-client
   payload URL that points to the Mac-side wired address. Do not expose Metro through a public
   tunnel merely to avoid local network setup.

The physical iOS 27 acceptance on 2026-10-29 proved both stages independently: the signed native
shell reached Expo Dev Launcher without the former `UIScene life cycle is required` failure, and a
wired local payload URL loaded the 1,370-module bundle into BeatNote's studio UI. Foregrounding
iOS Settings and returning to the existing BeatNote process restored the loaded song, waveform,
markers, playhead, and loop state. This verifies scene adoption, dev-client URL forwarding, and
basic scene reactivation. Physical Files/third-party Open In and background audio continuity remain
separate acceptance items.

## Local simulator workflow

### Interactive Xcode 27 workflow

1. Start Metro from the project root: `npm start -- --dev-client --localhost --port 8081`.
2. Open `ios/BeatNote.xcworkspace` in Xcode. If it does not exist, run `npx expo prebuild -p ios`
   first.
3. Select the `BeatNote` scheme and an iPhone simulator in Xcode's run-destination control.
4. Choose Product > Run or press Cmd+R. In Xcode 27, the simulator screen is presented through
   Device Hub; keep Metro running while testing.

JavaScript edits normally refresh through Metro. After changing native dependencies, Expo config, or
config plugins, regenerate the native project and run again. `npm run ios` remains the Expo shortcut
on setups where Expo can resolve the installed Simulator app; on this Xcode 27 host it currently
stops with `Can't determine id of Simulator app`, so use Xcode's Run action instead.

The minimum iOS deployment target is 15.1. `expo-build-properties` sets the app target, while
`plugins/withIosPodDeploymentTarget.js` aligns third-party pods that otherwise declare obsolete
deployment targets rejected by current Xcode versions.

`package.json` and `app.json` must carry the same user-facing semantic version. `npm start`,
`npm run ios`, and `npm run android` run `npm run check:version` first; the check also validates an
existing generated iOS project's `CFBundleShortVersionString` and `MARKETING_VERSION` values.
`plugins/withVersionConsistency.js` reapplies the Expo version during every iOS prebuild. The native
build number (`ios.buildNumber`, `CFBundleVersion`) and Android `versionCode` are separate monotonic
release counters and are not expected to equal the semantic version string.

## Automated iOS acceptance tests

Run `npm run test:ios:ui` to regenerate the native project, add the shared `BeatNoteUITests` target,
build the app and test runner, stage local audio/CSV fixtures in the simulator's Files-visible
Documents folder, and run the XCTest UI suite. The target and shared Xcode scheme are generated by
`plugins/withIosUiTests.js`; test source is tracked under `tests/ios/` so it survives prebuild.
The test helper browses to Files > On My iPhone > BeatNote when Recents is empty, so a fresh
simulator works without prior picker history.

The suite covers app launch and document-picker presentation, settings drawer open/close,
audio selection/playback, marker/annotation entry (including annotation while playback continues),
durable-copy and per-song draft restoration after a cache purge, confirmed CSV replacement, CSV
export to the iOS share sheet, background/foreground playback, long-track overview tap/drag seeking,
landscape waveform and controls, Open In delivery into the retained Music Library, and native
automatic-BPM detection with half/double resolution, preview/apply/restore, and anchor nudging. The
150-second `long-test-track.m4a` fixture is copied to Files > On My iPhone > BeatNote for manual
simulator checks.

The aggregate command builds once, then reinstalls and restages the app before each retained picker
journey. This isolates Files-provider and app-container state that XCTest otherwise retains between
cases. Open In remains a separate `simctl openurl` invocation with its own result bundle.
`IOS_TEST_ONLY=<test-name>` runs one XCTest case; `IOS_SIMULATOR_ID=<simulator-udid>` chooses a
specific simulator. Otherwise the script uses the booted iPhone or prefers iPhone 17 Pro. These UI
tests run headlessly from the command line and do not replace interactive Device Hub or physical
device acceptance.

`testAudioAnnotationAndProjectRestore` launches once with
`BEATNOTE_TEST_PURGE_CACHES=1`. The `__DEV__`-only lifecycle hook removes `Paths.cache` before boot,
proving that playback and the unsaved marker restore from the managed Music directory and draft
rather than from the picker cache.

Real audio-session interruptions (such as calls), physical-device audio behavior, touch/rotation
visual quality, and completing a share to an external destination remain manual acceptance checks.
The test command starts Metro only when port 8081 is not already serving the app. Set
`PLAYWRIGHT_PORT=8082` when running web E2E alongside a simulator Metro server on 8081.

```bash

eas build --platform ios --profile preview

# Submit to TestFlight
eas submit --platform ios --profile preview
```

## iOS-specific features

### Share sheet (import/export)

- `plugins/withAudioDocumentTypes.js` preserves the `.beatnote` editor declaration and appends MP3,
  WAV, M4A/MPEG-4, AAC, OGG, and FLAC document types. It also supplies imported OGG/FLAC UTIs.
- Open In URLs are retained by the `library-storage` app-delegate subscriber until JavaScript and
  library boot are ready, then pass through the same serialized import/switch pipeline as the picker.
- `LSSupportsOpeningDocumentsInPlace` is provisionally `false`. iPhone 17 Pro / iOS 26.2 simulator
  testing delivered Inbox URLs and preserved the `.beatnote` declaration under both values; the
  final choice still requires the physical-device Task 1.2 matrix.
- CSV export uses the existing iOS activity sheet. Completing a share to an external app remains a
  physical-device acceptance item.

### Files app integration

- User-visible imports may originate in Documents/Files, but BeatNote copies audio to
  `Library/Application Support/BeatNote/Music` and stores only relative managed paths.
- `LibraryStorage` creates this Music directory, applies `NSURLIsExcludedFromBackupKey`, verifies the
  flag, and supplies streaming MD5 and UUID primitives. Documents remains Files-visible for fixtures
  and exports when `UIFileSharingEnabled` is set.

### iCloud sync

- Use `expo-file-system` with iCloud container paths
- Requires `iCloud` capability in the Apple Developer portal and `com.apple.developer.icloud-container-identifiers` entitlement
- Project files (`.beatnote`) sync automatically once written to the iCloud container path

### Background audio

- Implemented for playback: `useCustomAudioPlayer` configures `expo-audio` with
  `shouldPlayInBackground: true`, `playsInSilentMode: true`, and `interruptionMode: "doNotMix"`;
  the exclusive interruption mode is required by Expo Audio for iOS to associate the player with
  Now Playing. `app.json` declares `UIBackgroundModes: ["audio"]`.
- While a local song is loaded, the player is registered with `setActiveForLockScreen`, publishes
  its library display title to iOS Now Playing, and mirrors remote play/pause/seek status back into
  the studio store. V1 exposes play/pause, timeline seeking, and ±10-second skip controls; queue
  Previous/Next remain in-app because the installed Expo Audio API does not expose those
  remote-command mappings.
- The simulator verifies that playback time advances while backgrounded and that the UI recovers
  when foregrounded. Test Control Centre metadata/commands, calls, route changes, and real-device
  audio interruptions before release.

### Haptic feedback (tap-to-beat)

- Use `expo-haptics` for light impact feedback on marker placement
- Keep it optional — add a toggle in settings

## App icon and splash assets

`assets/beatnote-icon-source.svg` is the untouched Recraft export and is never edited. The shipped
artwork derives from its bar and diamond paths:

| File | Purpose |
| --- | --- |
| `assets/beatnote-icon.svg` | Full-bleed `#1E1C1D` square; source for `icon.png` and `favicon.png`. No rounded corners, because iOS applies its own mask. |
| `assets/beatnote-mark.svg` | Transparent mark only, for reuse. |
| `assets/beatnote-icon-shield.svg` | Alternate using the in-app marker shield instead of the diamond; not shipped. |
| `assets/adaptive-icon.png` | Transparent mark at 68% so Android masks cannot clip it; background `#1E1C1D` in `app.json`. |
| `assets/splash-icon.png` | Transparent mark at 70%; splash background `#1E1C1D` in `app.json`. |

The artwork is scaled to 92% and lifted 12 px for optical centring, because the bars hold most of
the visual mass below the bounding-box centre. Regenerate PNGs from the SVGs (Inkscape or
ImageMagick) rather than editing them by hand, and keep the splash and adaptive backgrounds equal
to the icon's charcoal.

## Bundle identifier

`com.beatnote.app` — set in `app.json`. Do not change without updating the Apple Developer portal.

## Generated Info.plist ownership

`app.json` owns `UIFileSharingEnabled`, `UIBackgroundModes`, and the BeatNote Project document
declaration. `plugins/withAudioDocumentTypes.js` idempotently owns the audio declarations,
OGG/FLAC imported UTIs, and provisional `LSSupportsOpeningDocumentsInPlace = false`. Never edit the
generated `ios/BeatNote/Info.plist` directly.

## Native modules

The following features require native iOS modules (Swift bridging via Expo Modules API):

| Feature | Module location | Status |
| --- | --- | --- |
| Demucs CoreML inference | `modules/stem-separation/` | Planned |
| Waveform extraction (mobile) | `modules/beatnote-waveform/` | Implemented |
| App-owned music storage, backup exclusion, hashing, UUIDs, and Open In URL delivery | `modules/library-storage/` | Implemented |

Use `expo-modules-core` to write these as Expo Modules (Swift + TypeScript interface). Do not use bare `react-native` native modules.

Pitch-preserving playback from 0.5× through 2× uses `expo-audio` directly and does not require a
custom native module (ADR-011). Physical-device acceptance must still assess musical quality,
Bluetooth output, interruptions, background continuity, loops, and live rate changes.
